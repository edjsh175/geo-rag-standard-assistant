# AI 回答可读性设计

日期：2026-10-08
状态：用户已于 2026-10-08 确认；已实施并完成源码审查、测试与浏览器验收

## 目标与第一性原则

回答的价值是帮助用户获得判断，而不是完整复述工具输出。降低获得结论、判断可信度、找到依据的阅读成本，同时保留事实、引用和不确定性。

用户截图暴露的问题是结论、区域、覆盖限制、数十条标准名称以及内部字段处于同一段落、同一视觉层级。单纯增加行高无法解决信息组织问题。

## 已确认的源码事实

- `frontend/src/index.css:222-345` 已有 Markdown 标题、段落、列表、表格等基础样式。
- `Backend/app/services/agent/answer_generator.py:193-207` 的生成提示仅约束证据和 JSON 协议，没有阅读结构要求。

- 标准目录和浏览器执行回执以 JSON 进入证据。展示正文需要解释其含义，而不能直接复述内部字段。

- 当前 App 只逐事件更新执行过程，最终答案在 result 到达后展示。此任务不改变流式传输协议。
- 历史消息内容原样恢复，并使用同一个 Markdown 渲染路径。

## 方案比较

1. 仅修改字体、行高、段落间距：成本低，但无法为单段正文创造语义层级。
2. 改进生成表达、单元拼接和 Markdown 展示：推荐。利用现有证据契约和渲染依赖，解决信息组织与视觉阅读两个问题。
3. 新增结构化展示块协议和专用业务卡片：适合长期扩展，但需要修改生成 schema、审查、发布、历史兼容等边界；本次收益不值得增加这些改动。

## 推荐设计

### 生成内容

- 简短问题用简短段落直接回答，不强制套用固定栏目。
- 长回答先给直接结论和重要限制，再组织依据或清单。重要限制使用独立段落，不混入可折叠清单。
- 一个自然段表达一个主要意思；长清单采用 Markdown 列表，比较多项属性时采用表格。
- 标准目录根据证据中的真实适用范围分组，例如“四川地方标准”和“全国标准”。不依据编号或名称猜测适用范围。
- 将机器字段表达为用户含义，例如“已确认适用”“适用范围待核验”“当前结果不保证完整”。只在用户要求调试或字段说明时展示原始字段。
- 明确区分总计、当前页、范围未判定和分页状态。浏览器执行回执只能支持地图执行事实，不能替代标准适用性证据。
- 每个 AnswerUnit 保留原有事实与引用绑定。格式优化不增加没有证据支持的判断。
- AnswerUnit 之间使用空行形成独立 Markdown 段落；各 unit 内的列表和表格必须构成完整的 Markdown 块。
- 同时检查受限修复路径的表达要求，不改动必须原样保留的单元。

### 展示内容

- 提取专用回答 Markdown 组件，供 Chat 中所有 assistant 答案使用。
- 保持现有主题，增加段落与分组间距，让标题、正文、标准编号和引用具有清楚的层级。
- 超过 6 条的顶层列表默认展示前 6 条，显示剩余条目数量，允许展开和收起；嵌套列表跟随所属条目完整显示。折叠基于解析后的列表结构，不按分号或句号猜测内容。
- 结论和重要限制始终可见，不能被列表折叠隐藏。普通段落不自动截断。
- 表格和代码块在自己的容器内横向滚动，避免撑宽或被消息气泡裁切。
- 继续支持当前参考资料点击与历史消息恢复。旧的纯文本答案保持原始含义，不在浏览器端自动改写事实或猜测分组。
- 折叠按钮提供清楚的中文标签、展开状态和键盘操作；消息更新时不混用不同消息的展开状态。

## 修改范围

- 后端：回答生成与受限修复提示、AnswerUnit 文本拼接，以及针对段落与引用保持的测试。
- 前端：Chat 的答案渲染、独立 Markdown 组件及其局部样式，以及列表折叠和宽内容展示测试。
- 不将工具过程面板的 JSON 展示和事件字段投影纳入本次核心改动。

## 验收

1. 两个普通文本 AnswerUnit 显示为两个自然段，引用归属与发布内容仍然一致。
2. 长标准清单按证据范围分组，每条独立阅读；列表折叠可以展开且不丢失条目。
3. 简短答案没有多余栏目；重要限制不会因折叠而消失。
4. 混合 Markdown、嵌套列表、表格、代码块可正常展示；长表格和代码不会破坏聊天栏宽度。
5. 历史恢复复用同一渲染组件，已有引用点击行为保持可用。
6. 执行相关后端测试、前端渲染测试、lint 和 build，并在浏览器中检查窄聊天栏及明暗主题。

## 已知限制

生成提示能引导表达，不能保证模型永远输出理想结构。此次通过确定性的段落拼接与结构化 Markdown 展示修复可控制部分；不通过前端正则重写模型语义。旧的单段历史答案不会凭空获得真实的业务分组。

首轮回答优化时，当前聊天的工具列表未提供 AOCI MCP，因此当时仅依据源码与本地渲染实验定位，没有更新正式仓库认知索引。2026-10-08 跟进已完成本地 MCP stdio 握手与完整 Overview/Challenge 校验，并修正外层工作区缺少项目注册的问题；后续增量维护结果以 AOCI 事务回执与 Verify/Check 记录为准。
