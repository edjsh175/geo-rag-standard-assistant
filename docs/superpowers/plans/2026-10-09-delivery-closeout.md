# 2026-10-09 GeoAI 交付收口计划

Goal: 修复核验发现的安全缺陷与基础组件错误，以本次实际执行结果重建交付证据，移除超出证据的交付宣称。
Architecture: 保留现有 Agent 协议与数据库状态权威。先验证运行入口和现有并发控制，避免未经验证直接启用集群模式；上传安全与分布式基础组件按文件责任边界修复。无法在本机验证的外部部署能力明确列入验收事项。

- [ ] 上传安全：恶意 filename/upload_id、尺寸、分片一致性先加失败用例，再实现输入验证和目录约束，验证真实路由错误转换。
- [ ] 分布式基础组件：验证竞争超时不能跨锁降级、同键连接所有权、Redis订阅与取消清理；修复并补行为测试。根据已有状态机选择安全的接入方式。
- [ ] 工具审批：核对已有确认机制，避免把 denied 宣称为审批挂起；在不引入未经设计的新公开协议的前提下修正功能范围。
- [ ] 完整复验：后端 pytest、前端 lint/test:unit/build、E2E preflight、历史归档只读汇总；归档完整输出及退出码。真实 E2E 只有环境准入满足时执行。
- [ ] 报告对账：更新六阶段报告的过时总结；区分当次回归、历史 E2E、模拟检索指标、构建chunk和首屏下载、配置存在和云端执行。
- [ ] 独立审阅并处理影响收口的发现；最终复核新增改动与验证记录。

Constraints: 不覆盖用户现有未提交改动，不commit/push，不猜测云端CI结果，不把历史E2E当作当次回归。现有AOCI MCP工具在本会话未提供，不能制造索引或维护收据。
